# 装配图明细表齐套性检查

## 功能边界

本功能检查**本次选定导入集合**中的工程图是否齐套：读取装配体工程图的明细表（BOM），提取其中的零部件条目，再按原始文件名核对对应工程图是否也在同一集合中。

- 不读取 Excel 结构 BOM，不要求用户上传 Excel。
- 不先重建完整装配树；全量模式逐张装配图独立识别、独立汇总。
- 不做数量、材料、尺寸等工程一致性审查；数量只展示。
- “存在”只指**本次选定集合**内存在，不能用其他批次或图纸库其他文件补齐。
- 第一版沿用现有导入能力，实际核对 PDF、PNG、JPG、JPEG、TIFF、BMP、WebP；`.SLDPRT`、`.SLDASM` 是模型，不算工程图；未导入的 `.SLDDRW`、`.DWG`、`.DXF` 不参与匹配。

## 操作入口

工作台顶部导航进入 **齐套性检查**（`/kit-check`）。

1. 在“本次检查集合”中勾选本次导入的工程图。新上传会记录一个批次号，页面默认只勾选最近导入批次（避免用更早批次的同名文件自动补齐）；可以按图名或文件名筛选，也可以手动勾选多个批次。
2. 选择模式：
   - **检查全部装配图**（默认）：逐张扫描集合内工程图，识别有效装配明细表并汇总。
   - **手动指定总成图**：从本次集合选择一张总成图，读取其明细表；匹配到的文件若也有有效明细表，则沿引用继续展开。
3. 点击“开始检查”。后台任务显示已检查图纸数、当前步骤和进度。
4. 结果按来源装配图分组。主清单显示序号、代号、名称、备注、数量、匹配文件和存在/不存在；免查项在折叠区域显示原因；提取问题单独展示。
5. 可只看不存在项、只看待复核项；可预览来源图/匹配图或打开原文件；可导出 CSV（UTF-8 BOM，Excel/常见表格软件可直接打开）。
6. 识别失败或部分页未检查时，可点击“重试识别”。只有存在失败/部分页图纸时才可重试；检查中存在人工修正时重试会被阻止，避免覆盖修正。单条提取字段可点“修正”，保存后立即重新匹配，不重新调用模型。

## 确定性规则

### 备注免查

仅当备注明确等于以下值时免查：

- `标准件`
- `外购件`
- `无图`

支持统一全角/半角、首尾空格、括号包裹和明确标签前缀（如 `备注：标准件`），也支持由明确分隔符连接的多个豁免标签（如 `标准件、外购件`）。以下情况**不**豁免：

- `非标准件`（不因包含“标准件”而命中）
- `标准件；表面处理` 等复合备注
- `无图纸` 等语义不明确的变体
- 空备注；即使名称是“螺钉”“螺母”也必须继续查图

无法明确判定的复杂备注保留原文并提示复核。豁免只作用于当前明细表条目，不按代号传播到其他装配图。

### 文件名匹配

使用**原始上传文件名**（不是内部存储名），去掉最后一个扩展名后，只接受四种完整形式：

1. `代号`
2. `代号-名称`
3. `代号_名称`
4. `代号 名称`

匹配前执行 NFKC（全半角统一）、首尾空白和连续空白规整；代号拉丁字母不区分大小写；保留点号、前导零和连接符。匹配是完整相等比较，不做子串/模糊匹配，因此 `SK.CNC.0003` 不会匹配 `SK.CNC.00030`。名称相同但代号不同不算存在；同代号但名称不一致只作为候选提示，不自动判为存在。多个符合规则的文件全部保留。`~$` 开头临时文件会被忽略。

## 提取状态

| 状态 | 含义 |
| --- | --- |
| `ok` | 所有页面已处理，识别到有效明细表 |
| `partial` | 部分页面未处理/识别失败，或明细表行存在但部分字段无法确认 |
| `no_table` | 所有页面已处理，明确没有装配明细表 |
| `failed` | 明细表识别失败，或存在表格但没有可确认的代号 |

“没有明细表”“提取失败”“未处理页面”不会互相冒充。关键代号缺失、序号冲突、表格存在但文字无法辨认时，条目保留为待复核；不会生成确定的“不存在”，也不会显示“整套齐全”。检查集合中的原始文件被删除、检查任务未生成结果、或提取标记成功但没有任何明细表行时，也会将检查标为不完整。

## 数据与缓存

新增表（启动时自动创建，旧数据库无需手工迁移；`drawings` 表新增 `original_filename`、`batch_id`、`page_count`、`pages_processed`、`ocr_errors` 列，采用 `ALTER TABLE` 兼容）：

- `kit_checks`：检查任务、模式、检查集合快照、进度和最终状态。
- `kit_check_drawings`：以图纸 ID 为单位记录访问状态、页数、来源（root/scan/reference）、引用父条目和问题。
- `kit_check_items`：明细表行、原始行文字、位置、提取状态/问题、豁免原因、匹配结果、人工修正审计。
- `kit_extractions`：按“文件内容哈希 + 提取配置版本 + Qwen 模型 + 页数上限 + 现有 OCR 文本”签名缓存提取结果。

文件集合或匹配规则改变时只会重新匹配，不会复用旧匹配结果；图纸内容或识别配置改变时提取缓存失效。

## 配置

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `QWEN_OCR_MAX_PAGES` | `10` | 每张图最多检查的页数；超出部分标记未处理，不当作已检查 |
| `KIT_CHECK_MAX_DRAWINGS` | `200` | 单次检查集合上限 |
| `KIT_CHECK_MAX_DEPTH` | `50` | 手动模式子装配展开深度上限 |
| `QWEN_API_KEY` / `QWEN_VL_MODEL` | 现有配置 | 聚焦明细表识别复用现有 Qwen-VL 凭据与模型 |

> 明细表聚焦识别当前依赖 Qwen-VL。未配置 Key 时系统不会把“没读到”当作“没有明细表”，而是返回提取失败并提示复核；已有 OCR/PDF 文字层只能作为候选行来源，不能单独宣称齐套。

## API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/kit-check` | 检查页面 |
| `POST` | `/kit-checks` | 创建检查；JSON：`drawing_ids`、`mode`（`all`/`manual`）、`root_drawing_ids` |
| `GET` | `/kit-checks/{id}` | 任务进度、分组结果、统计 |
| `POST` | `/kit-checks/{id}/retry` | 重新识别失败/部分页图纸 |
| `PATCH` | `/kit-checks/{id}/items/{item_id}` | 人工修正代号/名称/备注/数量并重新匹配 |
| `GET` | `/kit-checks/{id}/export.csv` | 导出 UTF-8 BOM CSV |
| `GET` | `/kit-checks/recent` | 最近检查 |

## 验证记录（2026-10-28）

- 规则/服务/路由自动化测试覆盖：文件名四种完整形式、边界与前导零、大小写/全半角、名称相同代号不同、同代号名称不同候选、备注豁免/非标准件/空备注、删除必需 PDF、删除免查项、模型文件、同一零件多分组、手动展开、循环引用、重复引用、独立装配图、部分页/失败不报齐全、集合外文件不补齐、CSV 编码。
- 使用实际 Qwen-VL 对可读测试图纸（非示例目录、字体正常、文本可渲染）执行端到端：总成 1 张 + 子装配 1 张 + 零件 2 张；识别到 2 个装配组，3 条存在、1 条不存在、2 条免查；CSV 中文正常。全量模式与手动总成模式均执行，子装配引用来源可见。该验证使用真实模型调用，不是页面模拟数据。
- 示例目录 `齐套性检查示例图纸/` 中的 PDF 使用未嵌入的 `HYSWLongFangSong` 字体；PDF 渲染和 Qwen-VL OCR 均只能得到符号/乱码（例如 0002 的明细表文字无法辨认）。系统对这类图纸返回 `failed` 并提示复核，不会把乱码当作空表或“不存在”。这是示例 PDF 的来源限制，不是业务逻辑硬编码。真实场景中只要 PDF 字体嵌入/正常渲染，聚焦识别路径即可工作。
- 浏览器实际操作验证：检查页面加载、模式切换、全选/筛选、开始检查进度、分组结果、只看不存在、免查折叠、预览弹层、逐条修正后重新匹配、CSV 下载、失败/未完成提示。
