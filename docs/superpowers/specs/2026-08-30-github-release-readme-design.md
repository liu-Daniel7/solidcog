# SolidCog GitHub 发布与可复现 README 设计

## 目标

将当前开发工作区整理为只包含 SolidCog 产品代码的公开仓库，并重写 README，使一名不了解源码的用户能够在满足硬件和账号要求的全新 Windows 电脑上，仅按照文档完成安装、配置、启动和功能验证。

本次发布不包含任何比赛、申报、答辩或演示资料，也不提交本地数据库、上传文件、模型权重、API Key、缓存和运行日志。

## 发布范围

保留并提交：

- FastAPI 主应用及模块化 `app/` 代码
- `templates/` 前端页面
- WSL2 MechVL 本地推理服务
- Windows 与 WSL2 必需的启动、安装脚本
- 当前产品路径所需的 Python 依赖
- 自动化测试
- README、系统架构和直接服务于部署的技术文档

从 Git 仓库删除：

- 旧数据库迁移、重建和人工检查脚本
- 调试截图、临时裁切图片和一次性布局工具
- 已被 Qwen3-VL-Plus 替代的 PaddleOCR 下载与 Orange Pi 部署链路
- 与当前 Windows + WSL2 产品路径无关的旧安装脚本和旧技术文档
- 重复、过时或与实际代码不一致的说明

本机未追踪的比赛 Word、比赛 Markdown、演示 SVG、格式模板、文档转换脚本和 Ascend/Atlas 展示方案不提交，也不因本次 Git 清理而删除本机原件。是否彻底删除这些本地资料不属于本次任务。

## 官方复现路径

README 只提供一条主要路径，避免多个后端和过时平台造成歧义：

1. Windows 作为 SolidCog FastAPI 主服务运行环境。
2. WSL2 Ubuntu 作为 MechVL-4B-RL 本地推理环境。
3. DashScope `qwen3-vl-plus` API 用于图纸 OCR。
4. NVIDIA GPU 用于 MechVL 本地问答；文档明确最低与推荐内存、显存、磁盘空间。

README 中每条命令注明执行终端和当前目录。所有配置从 `.env.example` 复制生成，示例只使用占位值。

## README 结构

README 按实际操作顺序组织：

1. 项目定位、功能和双模型职责
2. 系统架构与数据流
3. 硬件、系统、账号及网络前提
4. 克隆仓库和 Windows Python 环境安装
5. DashScope API Key 配置
6. WSL2、CUDA 可用性与 MechVL 模型安装
7. 分别启动 MechVL 和 SolidCog 的命令
8. `/health`、主页、上传 OCR、问答的分阶段验证
9. 停止、重启、查看日志和日常启动
10. 常见故障排查
11. 目录结构、接口、测试与数据安全说明

README 不包含私人联系方式，不声明仓库中不存在的许可证，也不承诺未验证的平台支持。

## 复现验收

发布前验证以下内容：

- README 中的路径、脚本名、环境变量、端口和接口与代码一致。
- `.env.example` 覆盖启动所需配置且不包含真实密钥。
- 主应用可导入并启动，MechVL 健康检查接口可访问。
- 自动化测试全部通过，测试不读取或修改用户的正式数据库与上传文件。
- Git 暂存内容不包含 `.env`、数据库、上传内容、模型权重、缓存、比赛资料或私人信息。
- 仓库内不再引用已删除的脚本和旧 OCR/Orange Pi 主路径。

由于重新下载模型耗时且会产生大量外部流量，本次验收复用当前已成功运行的 WSL2 MechVL 环境，并核对安装脚本的静态命令。README 会区分“本机已验证”与硬件或网络差异可能导致的外部安装问题。

## 提交与发布

先提交本设计文档，再实施代码与仓库清理。实现完成后运行测试、检查 Git 差异和敏感信息，将产品更新提交到当前 `branch_test`，最后推送到 `origin/branch_test`。

不改写历史，不强制推送，不触碰当前本地数据库和上传数据。
