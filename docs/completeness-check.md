# 齐套性检查

齐套性检查用于确认 **本次提交范围内** 的图纸是否齐全、标题栏与明细表的必填项是否填写，并为疑似漏尺寸提供可复核的视觉线索。它只做存在性与空值检查，不判断图号、名称、版次、材料、数量、尺寸数值、公差或设计是否正确。

入口：工作台顶部 **齐套性检查**，或直接访问 `/completeness`。

## 1. 范围与边界

- 创建批次时必须手动勾选本次提交的图纸。系统不会默认把整个图纸库当作本批次提交。
- 图纸引用只在本批次已选图纸内匹配。图纸库中未选入的文件即使图号相同，也不会被当成已提交。
- 已支持 PDF、PNG、JPEG、TIFF（含多页）、BMP、WebP。**不支持 DWG/DXF 的原生解析**，请先导出 PDF 或图片。
- 不修改 `drawings` 中已有的标题栏、技术要求、全文 OCR 或上传原件。检查使用新的 `completeness_*` 表保存快照与结果。
- 不新增付费供应商，不调用新的模型或 API Key；检查本身是确定性规则。

## 2. 使用流程

1. 打开“齐套性检查”，填写批次名称。
2. 在图纸选择器中勾选本次提交的图纸，可把总图/子装图设为起始图。
3. 选择本次需要的标题栏必填字段与明细表必填列；尺寸复核可单独启用。
4. 创建批次。创建后仍可在批次页修改规则；规则版本会递增，旧结果保留但标记为失效，需要重新检查。
5. 点击“开始检查”。完成后查看汇总与逐项证据。
6. 点击某条结果的“查看原图证据”，可查看对应页面/区域、OCR 证据和人工确认按钮。
7. 可导出 CSV，或查看该图纸原有的 OCR 结果。

## 3. 状态语义

| 状态 | 含义 |
| --- | --- |
| 已通过 | 有可用 OCR/表格证据表明字段存在、非空，或引用图号在本批次中找到唯一匹配。 |
| 明确缺失 | 标题栏字段标签存在但值为空；明细表规则必填单元格为空；或本批次内确实找不到引用图号。 |
| 待确认 | 表格无法可靠识别、标题栏结构不清、OCR 无坐标、同图号多份文件、引用列有空行、尺寸存在视觉候选等。 |
| 检查失败 | 检查过程无法执行，例如原图缺失、无法渲染或 OCR 证据为空。**检查失败不等于缺失。** |

汇总始终分别展示“已通过 / 明确缺失 / 待确认 / 检查失败”的数量，不提供无法解释的单一齐套率。

## 4. 默认规则与自定义

默认标题栏必填字段：图号、图名、材料、比例、版次、日期。默认可选字段包括重量、设计/制图、校对/审核。

默认明细表必填列：序号、图号/代号、名称、数量。材料、备注默认可选。

用户可在创建批次时或批次详情页取消/勾选任意字段。至少需要启用一项检查。每次检查的结果保存当时的规则快照和 `rules_version`，规则修改不会静默改写旧结果。

注意：必填列是对 **所有数据行** 的规则要求。例如把“图号/代号”设为必填后，明细表中该列为空的行会被报告；如果客户标准允许部分行留空，应在该批次取消该列，或仅将名称/数量等实际必填列勾选为必填。

## 5. 图纸引用递归

1. 系统从已保存的 OCR 文本或 MinerU 原始结构化结果中恢复明细表。
2. 识别表头中的图号/代号、名称、数量等列；仅检查图号/代号列。
3. 将图号做全角/半角、大小写与空白规范化；排除标准件编号（如 `GB/T`、`ISO`、`DIN` 等）和明显不是图号的数值。
4. 只在与本批次成员的标题栏图号匹配时判定“已找到”。
5. 同一图号在本批次对应多份文件时标为待确认，不擅自选择其中一份。
6. 相同来源的重复引用合并为一条结果，并记录重复次数；不会重复递归。
7. 使用有向图遍历并在检测到循环时截断；同时记录层级和循环提示，不会无限递归。
8. 未识别到明细表、低置信度表格、图号列为空或只有部分行有图号时，标为待确认，不会给出“无需下级图纸”的确定结论。
9. 如果本批次其他已选图纸的标题栏图号无法识别，未匹配引用会降为待确认，避免把“可能是这张图纸”的匹配误报为确定缺失；若目标图纸的图号本身来自版式推断而非明确标签，匹配也不会直接判为已通过。

结果包含来源图纸、页码、表格序号、行号、原始图号、匹配文件或候选文件。页码以实际页面 1 为起点；表格与行号在界面/CSV 中按人类可读的 1 开始编号。

## 6. 标题栏与明细表证据

- 标题栏字段标签与值来自已保存的标题栏 OCR；如果 MinerU 原始表格存在，还会使用单元格行列关系修复合并单元格排列。
- 只有在标题栏中看到字段标签、但没有相邻非空值时，才报告“为空”。
- 没有定位到字段标签/值时，报告待确认，避免把 OCR 漏识别误报为漏填。
- 没有明确“标签—值”关系、只靠版式/模式推断出的标题栏值也只作为线索，状态保持待确认，不会升级为已通过。
- 明细表逐行检查规则必填列。每个空单元格报告具体表格、行、列、字段和表格区域。
- 可选列不参与空值判定。
- 表格结构低于 70% 规则置信度、表头无法识别或字段不确定时，不自动判定缺失，统一标为待确认。

## 7. 尺寸标注复核：已验证能力与限制

尺寸模块是 **保守的视觉复核提示**，不是尺寸设计完整性证明，也不会把任何图纸自动判为“尺寸齐全”。

当前实现：

- 以原始栅格页为基础，识别封闭的孔、槽和封闭轮廓候选区域；
- 排除页面边框、分区字母数字、标题栏区域、低对比页面和明显文字笔画孔洞；
- 当 OCR 有坐标时，尝试关联附近的尺寸文字；
- 对每个候选给出页面、归一化边界框、候选类型、规则信心和“邻近尺寸文字 / 未发现邻近尺寸文字”的说明；
- 所有候选及整图尺寸复核汇总一律为 **待确认**，要求工程师对照原图确认。

已验证能力：

- 使用合成 PNG/TIFF 测试封闭圆孔、长圆槽、封闭轮廓的候选定位；
- 验证多页 TIFF 会检查后续页面；
- 验证页面证据裁剪使用结果所指页面，不会把第 2 页显示成第 1 页；
- 在本地图集样张上能给出需要复核的孔/槽/轮廓区域。

明确不包含：

- 不解析 DWG/DXF，不读取 CAD 实体、尺寸链或约束；
- 不识别未写出的尺寸线/箭头或开放轮廓的“应有尺寸”；
- 不判断尺寸数值、公差、基准、几何公差或设计意图；
- 不判断位置关系、装配关系、视图间一致性或跨页尺寸；
- 不能保证 OCR 已识别所有尺寸文字；Qwen 文本没有坐标时，无法把尺寸文字与图形区域关联；
- 不保证所有封闭区域都是真实特征，因此结果必须人工复核。

单个批次默认最多 100 张图纸，可用 `MAX_COMPLETENESS_DRAWINGS` 调整。默认自动几何扫描每张图纸前 8 页，可用 `COMPLETENESS_DIMENSION_MAX_PAGES` 调整；超出页数会显示限制说明，不会静默宣称已检查全部页面。图像分辨率、扫描清晰度和复杂剖面图都会影响候选召回/误报。

## 8. OCR 证据与旧数据

- MinerU 的原始 JSON（位于 `mineru_results/`）包含页块 bbox；检查时会将其规范化为页、块、表格、单元格证据。
- Qwen 现有记录主要只有合并后的文本，没有逐 token/bbox 坐标。系统会从制表符/竖线分隔的文本重建表格，但会明确标记为文本重建，并保留“无坐标”的局限。
- 原始 `drawings` OCR 字段不会被回写；新证据表为 `completeness_ocr_pages/blocks/tables/cells`。
- 旧数据库通过 `init_database()` 的幂等加法迁移自动获得新表；旧图纸、旧 OCR、翻译和检索继续可用。
- 如果 MinerU 原始结果缺失或损坏，会回退到已保存文本并产生待确认提示。
- 结果中的“规则信心”是规则/证据置信度，不是模型概率；模型本身没有返回的置信度不会被伪造。

## 9. 结果、人工确认与导出

每条结果保存：

- 规则版本、检查类别、状态；
- 来源图纸快照、页码、表格/行/列；
- 归一化边界框（如有）；
- 规则信心、OCR/表格证据 JSON；
- 人工确认状态（未确认/已确认有效/已排除）和备注。

CSV 报告包含汇总状态行和逐项明细，列有来源文件、页码、表格、行、列、字段、说明、匹配文件、规则信心、人工确认和 OCR 证据。所有用户输入、文件名和 OCR 文本在 CSV 中做公式注入防护；界面使用自动转义。

## 10. API

页面路由：

- `GET /completeness`
- `GET /completeness/batches/{id}`
- `POST /completeness/batches`
- `POST /completeness/batches/{id}/start`
- `POST /completeness/batches/{id}/rules`
- `POST /completeness/batches/{id}/delete`
- `GET /completeness/batches/{id}/report.csv`
- `GET /completeness/results/{id}/image`

JSON/API 路由：

- `GET /api/completeness/batches`
- `POST /api/completeness/batches`
- `GET /api/completeness/batches/{id}`
- `POST /api/completeness/batches/{id}/start`
- `POST /api/completeness/batches/{id}/rules`
- `DELETE /api/completeness/batches/{id}`
- `GET /api/completeness/results/{id}`
- `POST /api/completeness/results/{id}/review`

示例：

```bash
curl -s -X POST http://127.0.0.1:8000/api/completeness/batches \
  -H 'Content-Type: application/json' \
  -H 'Origin: http://127.0.0.1:8000' \
  -d '{"name":"总装提交检查","drawing_ids":[1,2,3],"start_drawing_ids":[1],
       "rules":{"required_title_fields":["drawing_no","drawing_name","material","scale","revision","date"],
                "bom_required_columns":["sequence","drawing_no","name","quantity"],
                "dimension_check":true}}'

curl -s -X POST http://127.0.0.1:8000/api/completeness/batches/1/start \
  -H 'Origin: http://127.0.0.1:8000'
```

所有写操作和报告/证据读取均执行本机来源校验；非本机 `Origin` 返回 403。重复启动使用原子状态占位，正在检查的批次返回 409，不会产生重复结果。删除图纸会清理批次成员并使其结果失效为待确认；检查运行期间禁止删除相关图纸。

## 11. 数据表

- `completeness_batches`：批次、状态、规则快照/版本、起始图、时间与错误。
- `completeness_batch_drawings`：仅包含本批次选入的图纸。
- `completeness_ocr_pages/blocks/tables/cells`：检查时的结构化 OCR 证据快照；单元格保留行、列、合并跨度、文本和可选 bbox。
- `completeness_references`：从明细表提取的图号引用及匹配状态。
- `completeness_results`：状态、来源、页码/行列、bbox、规则信心、证据 JSON 和人工确认。

## 13. 已知限制

- 图号识别基于常见字母数字图号模式；纯数字图号只在带“图号/代号”标签或明细表图号列中启用。特殊编码格式需要扩展规则。
- Qwen 的 OCR 结果没有坐标；标题栏/明细表 evidence 通常只能定位到页和整张表，不能精确定位到单元格。
- 表头合并过于复杂、文本被压平、扫描旋转或低清时，明细表会被标为待确认而不是猜测。
- 尺寸模块召回率有限、候选可能含误报；必须在原图上人工复核。
- 当前没有公网账号/权限系统，部署时仍需额外的网络访问控制。
